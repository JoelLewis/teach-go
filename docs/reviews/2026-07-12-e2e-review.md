## Verdict

Domain model and IPC are in good shape and the core loop (play → coach →
review) works live with KataGo and the LLM both active. The risk is
concentrated in review-session lifecycle, undo invariants, and
model-download integrity.

## Code findings (Codex, severity-ordered)

1. **High — `src-tauri/src/commands/review.rs:103-105,232-248`** — Review
   marks itself complete on missing/failed engine responses;
   `analyzed_positions = total_positions` even with partial analyses.
2. **High — `src-tauri/src/llm_support.rs:49-52` + sensei-llm
   `store.rs:116-121`** — A truncated GGUF already at the new layout path is
   treated as complete; interrupted download → corrupt model load at startup.
   (Upstream fix belongs in sensei-kit: verify size/sha before trusting an
   existing file.)
3. **High — `crates/gosensei-core/src/game.rs:203-220`** — Undo doesn't
   restore captures, ko, or pass state: capture counts stay inflated; ko
   recapture can become legal.
4. **Medium — `game.rs:216`** — Undo always flips `current_color`, wrong
   after resignation or two-pass game end.
5. **Medium — `review.rs:123-145` + `gosensei-katago/client.rs:40-47`** —
   Timed-out pending query IDs never removed; malformed KataGo JSON silently
   dropped.
6. **Medium — `review.rs:237-248`** — No generation token: a stale
   `start_review` task can write into a newer session and emit a bogus
   completion event.
7. **Medium — `src/views/ReviewView.svelte:32-35,68-79`** — Initial review
   can start twice (imperative call races the `$effect`), duplicating
   listeners and backend analysis.
8. **Medium — `src-tauri/src/commands/llm.rs:27-29`** — `try_lock()` failure
   read as "not loaded"; concurrent callers can double-download/load the
   ~3 GB model.
9. **Medium — `game.rs:237-260` + `commands/sgf.rs:59-64`** — Illegal SGF
   moves silently skipped; malformed record loads "successfully" truncated.
10. **Low — `src-tauri/src/db.rs:127-128`** — Migration swallows every
    `ALTER TABLE` error, not just duplicate-column.

Migration check: model-layout repair issue found (#2); Timeout/ParseError
mapping OK; `filter_channels: false` preserved OK; `n_ctx: 512` preserved
and unit-asserted OK. No `date()`-without-`'unixepoch'` bug here (the chess
app shipped one).

## UX findings (live run)

1. **Medium — Resign is one click, no confirmation.** Ends the game
   instantly (chess has an inline confirm). Misclick = lost game.
2. **Medium — Problems library leaks raw SGF metadata.** Titles like "GZP1",
   "GZP2" (duplicated), "Black to play. https://gogameguru.com/" (URL in
   UI); every entry "~1 dan · Life & Death · 19×19" although category filter
   chips exist. (Screenshot `go-problems.jpg`.)
3. **Low — "Mistake ›" navigation lands on moves badged "Excellent"** (top
   score-loss list with no threshold; "Top mistakes at moves: 2, 1, 3" is
   also unsorted). Confusing in short/clean games.
   (Screenshot `go-review-mistake.jpg`.)
4. **Low — Settings gear is icon-only with no aria-label** (title only);
   home-screen text bleeds through the translucent settings modal.

What worked well: new-game config (board size / opponent / color / strength
slider), stone placement and engine replies (~1 s), immediate coaching with
classification badges, review screen (win-rate graph, per-move score loss,
territory toggle, practice-problem generation), Progress view (rank estimate
+ six-axis skill radar), SGF import entry point, save/load.

## Not exercised

Undo-capture/ko live repro (code-confirmed only), hotseat/human opponent,
SGF import with a real file, practice-problem generation output, model
download flow (model already present), 13×13/19×19 boards.
